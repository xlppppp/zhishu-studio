# Harness Studio

[English](README.md) | 中文

本地应用共创工作台，支持需求导入、参考截图、四部分方案编辑、Harness 开发任务和源码交付。Python 3.11+ 通过标准库提供界面与 API，不需要先构建整个仓库的 Node 项目。

## 本地启动

在仓库根目录执行：

```sh
python3 studio/server.py
```

打开 <http://127.0.0.1:3088>。未连接 Harness 时，也可以创建项目、上传最多四张 PNG/JPEG/WebP 参考截图（每张 3 MB）、编辑方案、确认版本、查看与恢复历史。案例卡片提供示例需求，配图为示意图。

工作台优先使用同目录的 Harness 源码；先在仓库根目录执行以下准备命令，安装源码依赖并生成 headless 运行需要的类型元数据和本机原生组件；无需全局安装 dsh 或构建 Web 界面。

```sh
pnpm install
pnpm run build:native-system
node --import tsx/esm scripts/generate-typert.ts
```

需要真实 AI 分析和开发时，在启动工作台的终端配置模型密钥：

```sh
export GPT_GE_DEFAULT_API_KEY='your-default-group-key'
export GPT_GE_CODEX_API_KEY='your-codex-group-key'
python3 studio/server.py
```

也可指定已有、已配置的 CLI，无需再次安装：

```sh
export STUDIO_DSH_COMMAND='/absolute/path/to/dsh'
python3 studio/server.py --port 3088
```

`STUDIO_DSH_COMMAND` 按参数列表解析，不执行 shell 代码。工作台追加 `--profile headless`，通过标准输入传入任务，不会自动下载 CLI。默认选择相邻源码，以 Node 和 tsx 的 ESM hook 启动官方 CLI，并指定仓库的 tsconfig，保持开发任务的工作目录不变。仅在没有相邻源码时查找全局 `dsh`；模型选择、凭据与工具权限仍由 Harness 管理。仓库根目录的 `.env` 不会自动复制到生成项目；请使用启动终端的环境变量或 Harness 自己的凭据配置。截图以本地文件路径传给 Harness，实际识图需要配置相应模型与图片读取工具；上传成功不代表模型已经理解图片。

## 使用流程

需求上传支持 .docx、.md、.markdown、.txt，最多暂存四个文件，每个 30 MB。上传只将原件保存在本机 requirement-uploads 缓存，不调用 AI，也不把正文插入补充说明框。浏览器保存轻量附件 ID 与补充文字，以便刷新后恢复。缓存引用在 24 小时后过期，下次上传时清理过期副本；「移除」删除选中的暂存副本。缓存总量上限 512 MB，限制遗留文件占用。此单用户回环缓存不提供团队身份认证。

Word 暂存按顺序保留正文段落和嵌入图片引用，并插入段落编号与图片标记。PNG/JPEG/WebP 图片作为本地识图工具输入。不支持的图片格式会保留并提示；外链图片、图表、SmartArt 或嵌入对象需另附截图，不会自动下载。页眉页脚、批注与页面版式保留在原件中，不进入文字提取。Word 解压内容最多 120 MB，正文 XML 最多 30 MB，单张图片最多 30 MB，独立图片最多 80 张；单文件提取文字仍最多 30000 字符。Markdown 外链或本地路径图片同样需另附截图。

点击「开始我的项目」、命名并确认「创建并分析」后，原始附件、补充说明、参考截图一起保存并加入分析队列；支持仅上传文档创建项目。创建请求带幂等 ID，同一份输入重试不会创建第二次分析任务，修改输入需使用新 ID。分析启动失败时，项目和文档仍保存，并显示处理提示。项目附件是独立副本，不受暂存文件移除或过期影响，可在「原始需求」下载。新任务将原件、有序文字及图片元数据复制到私有工作区交接目录；分析提示要求实际读取支持的图片，并说明未读取或不支持的内容。模型和网关的识图支持仍需实际验证；上传成功不代表理解图片。源码交付 ZIP 不包含原始需求附件。完整附件流程需要重启 HTTP 与 Worker。

创建项目，填写需求并按需上传参考截图。通过 Harness 生成方案，或先创建手动草稿。方案包括 PRD、前端、后端接口、数据库四部分。可以直接编辑原文，也可以对某一部分或整个项目提交文字反馈。每次保存都会保留快照，并取消旧方案的确认与开发产物资格；旧编辑页不能覆盖新版本。

评审后确认当前版本，再单独点击开始开发。开发任务接收这一版方案，并在项目工作区中写入代码。任务输入、截图副本和结果文件放在项目工作区内的 `.studio/<任务 ID>/`，由服务校验并读取结果，不要求 Agent 写入工作区外。任务提交会返回 HTTP 202 与持久化任务标识，独立 Worker 按顺序领取执行；整个数据目录同时只执行一个 Harness 任务。同项目的修改可以明确加入队列，最多保留 10 个待处理任务；每项绑定提交时的方案版本。前置任务失败、取消、中断或方案发生变化时，后续任务会标为需要重新确认，不会按旧方案继续。任务状态区展示真实退出状态、超时、取消与结果校验失败；退出码为零但没有有效结果文件，也不会标记为完成。反馈和完整方案快照在重启后仍保留。HTTP 服务重启不会中断独立 Worker；SSE 推送真实执行阶段，并通过事件游标补发断线期间的状态。Worker 中断的任务标为结果未知，不会自动重跑。可在「版本记录」中的任务记录查看日志，并明确按当前方案重试；重试不回滚已有代码。

预览默认使用「体验模式」，保留页面自身的按钮、输入、标签页和弹窗交互。切换到「点选修改」后，点击元素会打开修改意见弹窗，携带标签、可见文字、CSS 选择器和页面路径；按 Esc 返回体验。切换模式不重载页面。这些定位信息不保证映射到具体源代码，右侧仍可直接输入文字反馈。

进入「开发与预览」时，条件满足且没有执行中任务会自动启动隔离运行预览，显示实际运行的前端；不再提供静态演示和停止按钮。条件缺失或启动失败时保留原因、检查、日志和明确重试入口，不循环重试。手动开发和退出工作台会停止所属预览；项目助手的问答和后台代码修改保留运行预览。生成文件可保留独立 `preview.html`，但不会作为运行失败时的替代页面。

「启动运行预览」支持 macOS 上已安装依赖的 Python ASGI + Alembic 应用，自动识别 `backend/app/main.py`、`.venv/bin/python` 与 `frontend/index.html`。其他目录结构可在工作区提供以下 `studio-preview.json`。适配器运行 `python -m alembic upgrade head` 和 Uvicorn，健康检查成功后在独立本地地址提供前端与 `/api/` 代理；不自动安装依赖或支持任意技术栈。

```json
{"kind":"python-asgi","cwd":"backend","python":".venv/bin/python","app":"app.main:app","frontend":"frontend","health":"/api/v1/health"}
```

运行预览使用项目目录下 `preview-runtime/<channel>/preview.sqlite`，停止后保留该预览数据库。`sandbox-exec` 限制文件访问与写入并禁止外部网络，根目录读取仅匹配 `/` 本身，不包含子目录；模型密钥不传入子进程。预览环境设置 `AUTH_ENABLED=false`、`SCHEDULE_ENABLED=false`、`DISPATCH_ENABLED=false`、`LLM_PROVIDER=extractive`，应用须遵守这些设置。前端仅能请求同源 API。启动失败可点「预览日志」查看；不满足平台或依赖要求时保留运行检查提示。手动开发前会停止运行预览；助手修改在保留的独立草稿中进行，已发布预览继续运行。退出工作台会停止预览，但不停止独立 Worker。

已确认方案且已有代码的项目可在审查待完成时启动运行预览；验收与导出仍受审查限制。源码哈希与审查副本共同排除浏览器安装、下载缓存、构建产物及私有数据库。标准库 HTTP 应用可配置 `{"kind":"python-http","cwd":".","script":"server.py","frontend":"public","health":"/api/v1/health","cookieNames":["mine_demo_session"]}`。脚本须接管 `STUDIO_PREVIEW_FD` 中的监听套接字描述符；`PORT` 标识该套接字，`DATABASE_PATH` 指定隔离的预览数据库。未指定 Python 可执行文件时使用工作台的 Python。仅代理列出的会话 Cookie，并按预览隔离名称；保留幂等与条件更新请求头。

项目助手跟随页面范围：方案设计页围绕方案讨论或修改，开发与预览页围绕代码讨论或修改。不再提供手动对话模式。智能体先在一次性过滤源码副本中判断消息意图；提问、诊断、讨论或含糊要求只回答，明确修改要求才生成独立的受检查方案或代码任务。代码修改要求已确认方案，并在保留的 `assistant-drafts/<job>` 源码副本中执行。失败或取消保留已发布代码和预览；成功后先检查原源码是否有并发改动，有冲突则不发布。运行预览使用冻结源码及数据库快照；替代版本通过健康检查后才切换，启动失败保留原网址并显示原因。新版本数据库使用启动时的快照，之后在旧预览中的测试操作不会复制到新版本。消息不会绕过审查或交付检查。页面选区附带元素文本、选择器、路径和坐标，不是像素截图；全屏框选后返回聊天。执行状态和日志位于打包交付右侧独立标签页，右侧仅放项目助手，原始需求显示在方案设计下方。

项目助手默认关闭，通过右下角按钮展开或收起；收起后保留对话和草稿，主工作区占满可用宽度。选取页面上下文时会展开助手以便提问。

「项目助手」旁的小三角展开当前项目的对话目录，支持重命名，当前标题可在目录中查看。重命名（包括「以前的对话」）会持久保存，不改变消息或模型上下文；过期名称不能覆盖新名称。新对话只创建持久空会话，不调用模型。旧的未分组消息归入「以前的对话」。切换对话恢复各自的消息与本地草稿；模型上下文仅包含当前对话最近 12 条消息，每条上下文消息最多 8000 字符；同时提供当前会话的完整消息档案，供智能体查阅更早的约束。自动创建的修改任务回复保留在原对话。新的自动判断消息要求 Worker 支持 `projectChat: 3`；升级时应等待任务结束，再重启网页服务与 Worker。浏览器发送消息前检查 HTTP 的 `assistantProtocol: 3`；旧后台会在本地被拒绝，不会停止预览。意图判断依赖配置的模型；请求不明确时应先澄清。

输入框的模型选择仅影响下一次提交的任务，可选项来自路由配置、降级模型和部署配置 assistantModels。紧凑的深色浮层支持 low、medium、high、xhigh、max 五档推理，默认 high；所选档位随项目草稿保存，提交时写入任务快照，助手自动创建的修改及审查沿用该档位并保留阶段分组，不改变已排队任务或全局策略。语音输入使用浏览器 SpeechRecognition API 识别中文，可能使用浏览器厂商的在线识别服务，需要麦克风权限。不支持的浏览器或权限拒绝会保留文字并提示原因。转写后可编辑，不自动发送；切换项目、离开工作台或发送消息会停止识别。Enter 发送，Shift+Enter 换行，输入法组字期间不发送。

对话模式、模型、文字、选中上下文、最近标签页及各部分编辑草稿按项目保存在当前浏览器；这不是服务端备份，清除浏览器数据或换浏览器不会恢复草稿。保存失败会就地提示。成功提交后才清除已提交意见，关闭弹窗保留草稿；旧版本编辑草稿不能覆盖新方案，可复制文字后放弃草稿再重新编辑。手动方案中的「待填写」占位文字必须完善后才能确认或提交开发。

同项目切换标签页保留已经打开的预览 iframe 及其内存状态。明确刷新、切换预览来源、准备就绪的新运行版本发布、打开其他项目或刷新浏览器仍会重新加载预览；预览内未提交表单不属于工作台文字草稿。运行准备检查只读取配置与文件，不执行应用代码；不满足条件时不能启动运行预览，并持续显示缺少项。依赖能否导入、数据库迁移和健康检查由启动阶段验证。

系统迭代可选择「样式快速修改」或「业务开发 / 交互修改」，默认使用业务路径；选择与意见一起保存，切页、重试不会改变路径。样式路径仅适用于已完成一版开发的项目，不重新生成 PRD。任务在独立临时副本中执行，只提供现有前端 CSS、HTML 和修改意见；不提供完整需求、四部分方案、参考截图、后端或数据库文件。可选目录为 `frontend/`、`client/`、`web/`、`src/`、`public/`、`assets/` 及工作区顶层；跳过隐藏目录、依赖与符号链接，单文件最多 2 MB，总量最多 10 MB。HTML 只接收已有 style 元素中的 CSS 内容，标签、属性、脚本、其他标记和文件增删均不可改变。组件内的 JS/TSX 样式、接口、权限、数据库及交互变更应选择业务路径。

任务通过任务级 overlay 关闭默认技能目录发现，只提供当前阶段指定的技能；这不是安装第三方 Cordis 插件。业务路径根据受影响的前端、接口与数据库执行必要测试，不要求为每次小改重新分析需求。文件接收前会检查越界与原文件变化；越界任务失败且不接收副本改动，模型也可用 `needsBusiness: true` 明确要求用户改选业务路径。样式任务成功后需要重新确认最终开发版本；未尝试传回文件的失败保留上一版开发和验收资格。任务仍由 Harness 负责进程隔离，副本和文件校验不替代执行沙箱；确定性夹具测试不代表真实模型已正确使用技能。

升级开发路径功能时，应先等待后台任务结束，再请求停止旧 Worker，并确认它已退出，然后重启 HTTP 与 Worker、刷新浏览器。旧 Worker 没有与进程匹配的 `worker-capabilities.json` 时，服务拒绝样式任务，避免它按旧的完整开发流程执行。`--stop-worker` 是停止请求，不保证返回时 Worker 已退出。现有队列不自动改变路径；未声明路径的旧任务按业务路径处理。

已有代码时，开发按钮先显示选择弹窗，默认“基于已有进度继续”：新任务读取当前源码、已保存预览、验证记录、已有修改意见与审查问题，保留已完成页面并补齐缺失部分；这不是恢复到原模型的精确步骤。已保存的开发检查点与当前确认方案、受检查源码一致时，“继续”直接进入审查；源码变化或旧任务没有检查点时，仍先通过开发任务检查现有实现。“重新开发”先将整个工作区保留在 `workspace-backups/<job-id>/`，再创建仅含本次任务输入的空白工作区。备份包含本地配置与数据，只保存在本机、不进入交付 ZIP，也不会自动过期；分享前需检查内容。目录切换中断且活动工作区缺失时，下次 Worker 启动会恢复原工作区。重新开发独立执行，不允许与已排队任务或后续提交重叠。旧客户端省略 `buildMode` 时沿用当前文件继续。启用前重启 HTTP 与 Worker，以加载 `workspaceRecovery` 能力。

静态预览按现有 `preview.html` 文件判断，不依赖任务完成状态；取消开发或审查后，已保存页面仍可查看，旧中断项目同样适用。它可能是部分成果或较早版本，不代表当前应用可运行或符合确认方案；验收与导出仍要求开发完成并满足审查条件。

## 分阶段模型与审查循环

可选 `fallback` 配置声明 `from`、`to`、`primaryRetries`。新 GPT 任务在 `gpt-6.1-sol` 失败后重试一次，仍遇到终止的临时模型错误时，使用 `gpt-6-sol` 恢复同一个持久化会话；首次重试仍默认等待两分钟。密钥或配置错误、取消、超时、缺少会话标识、进度读取失败及工具没有返回结果时停止，不自动降级。备用模型沿用提供方有限重试策略，本阶段不会切回主模型；各阶段（含备用模型）沿用所配置的分组与推理档位，新阶段仍从配置模型开始。模型是否可用需要网关验证；未保存 fallback 的排队策略保持原有行为。

`model-routing.json` 指定提供方、分析、开发与审查模型。所有阶段默认使用 `gpt-6.1-sol`。`stageProviders` 为需求分析/方案修改选择 `gpt-ge-default`，为开发/修复/审查选择 `gpt-ge-codex`；`reasoning: high` 是所有阶段及备用模型的默认档位；助手提交可以为该任务覆盖档位。新任务保存策略快照。默认 `reviewMode: focused`、`maxReviewRounds: 2`，最多修复一次后定向复验。`reviewMode: full` 保留反复完整审查的旧流程；未保存 reviewMode 的排队策略仍按旧流程执行。模型与网关可用性需另行实测。

定向任务在模型审查前解析可用的 Python/JavaScript 语法和 package JSON，不运行应用代码。最多检查 50 个文件、其中最多 20 个 JavaScript 文件，单文件最多 1 MB；这些检查不证明构建、运行或部署成功。检测到语法错误时先交给修复，不先消耗模型审查。开发返回有效结果后即可在审查期间查看静态预览。首次开发及检测到的权限/数据库变更做完整审查，其他迭代审查改动文件及直接消费者。修复后携带上轮问题定向复验及检查关联回归，不从头巡检全项目。文件检测和模型严重程度判断不能保证识别全部风险。

代码保留与审查待处理提示仅在已有开发结果且审查待处理或阻塞时，显示于“开发与预览”；“执行状态”不显示这条提示。

报告区分 critical/high/medium 阻塞问题、失败检查、low 一般建议及缺失证据。阻塞或未验证的版本保留代码和预览，但不能最终验收及导出；一般建议不阻止人工验收。审查未完成不会把已经完成的开发统一标成执行失败。开发或修复执行失败、取消及超时仍会停止任务，文件保留供检查。审查副本排除依赖、私有文件和数据库；缺少前提必须报告。报告属于模型证据，不是平台认证。原有任务时限覆盖全部调用和检查，不提供金额限额。纯样式修改保留隔离快改路径。

点击「继续修复审查问题」可将上一份报告与当前工作区一起提交；旧失败任务的报告仍对应当前方案和源码任务时也可继续。过期报告会被拒绝。局部改动审查后，在打包交付页执行「交付前完整审查」再确认最终版本；此操作直接审查当前代码，不先调用开发模型。首次完整审查与隔离样式修改不强制重复完整审查。人工验收前检查报告和基础检查结果；HTTP 验收与导出接口独立执行限制，不依赖按钮禁用。

当前任务结束后重启 HTTP 与 Worker；定向任务要求匹配的 focusedReview 能力标记。排队任务保留已保存策略。新增可选 reviewState、reviewStatus、scope、finalReview、localChecks 字段，不涉及 SQLite 结构或 Harness Session 迁移。

## 文档与全屏评审

新的需求分析与方案修改任务以中文 HTML 片段输出 PRD、前端、后端、数据库四部分。PRD 包含业务流程图，适用的后端与数据库设计包含时序图和 ER 图。历史 Markdown 继续可读。本地渲染使用 Marked 16.4.2、DOMPurify 3.4.16、Mermaid 11.17.2，并移除可执行 HTML 与外部资源。图表错误时保留原文并就地提示修改。编辑原文会创建新方案版本；旧方案不会自动补出缺失的图表。

在「开发与预览」选择「全屏预览」，生成应用的前端页面铺满屏幕，并隐藏工作台工具栏。悬浮保留「退出全屏」与「修改页面」入口；「修改页面」提供体验、点选或框选。全屏弹窗、任务状态与通知保留在预览容器内。普通预览的工具栏下只显示快捷键提示；任务总结保留在执行状态区，运行前提通过「运行检查」查看。进入和退出全屏时保留同一个 iframe；浏览器拒绝 Fullscreen API 时使用窗口展开布局。在非编辑输入区按 Option/Alt + Shift + A 开启框选，在预览内拖动并松开后填写意见。Escape 取消选择，通过「退出全屏」退出全屏。区域反馈记录视口坐标、滚动位置、页面 URL 和采样元素描述/选择器，不包含截图，也不保证映射到源代码。仅用键盘时可点选元素或使用文字反馈区。生成应用的业务交互仍需由其自身实现。

需求分析加载 studio-analysis 及已安装的 [create-prd](skills/create-prd/SKILL.md)、[api-design-principles](skills/api-design-principles/SKILL.md)、[mermaid-diagrams](skills/mermaid-diagrams/SKILL.md)、[frontend-design](skills/frontend-design/SKILL.md)。业务开发涉及页面呈现时加载 frontend-design；受限样式任务仍只获得 frontend-style。Studio 分析适配技能负责四字段 HTML 结果协议，并将未明确需求列为待确认项，供评审时补充，而不会等待交互提问。API 指引覆盖权限、请求响应字段、校验、错误及适用的分页或幂等要求；同一次分析任务将核心需求对应到一致的页面、接口与实体。第三方技能目录保留许可证与来源文件摘要。重启 HTTP 与独立 Worker 后使用新的生成指引；排队任务保留原有输入。本地模拟测试不验证真实模型的遵循情况。

浏览器依赖已随项目保存，运行时不需要 CDN。安装仓库依赖后，执行 `node studio/build-web-assets.mjs` 可按仓库依赖锁中的版本重新复制。许可证文本保存在 web/lib 中的脚本旁。

## 交付与限制

源码导出要求开发任务基于已确认方案成功返回、用户确认这一轮最终开发版本，并检查 `README.md`、`Dockerfile`、`compose.yaml`、`.env.example` 与 `VALIDATION.md` 是否存在。ZIP 包含源码、方案与明确的部署验证说明，排除除 `.env.example` 外的 `.env*`、依赖、Git 信息、`.studio` 任务交接目录、符号链接、常见私钥文件和以 `.db`、`.sqlite`、`.sqlite3` 命名的数据库及其 `-wal`、`-shm`、`-journal` 伴随文件。分享前仍需检查源码，导出器无法识别任意代码中的秘密信息。

工作台尚未独立验证或实现 Docker 部署、后端联调、自动验收、关联设计的自动一致性检查与代码版本回滚。方案快照可以恢复为新版本；生成代码保存在一个可变工作区中，失败任务可能留下部分修改。开发提示词要求测试与部署说明，但任务结束和文件存在不能保证应用可部署运行。真实模型执行依赖有效的 Harness 配置，确定性测试不代表完成了模型联调。

服务仅监听本机回环地址，并检查 JSON 修改请求的同源信息与精确 Host。它是没有账号认证与团队隔离的单用户开发工具。项目独立目录不等于执行沙箱，工具隔离由 Harness 负责，只有可信本地用户应启动任务。不要通过公网端口或隧道暴露此服务。

## 数据与配置

项目、截图、方案历史、请求、任务日志与生成代码默认保存在 `studio/.data/`，不纳入 Git。项目、任务和 SSE 事件以 `studio.sqlite` 为准；首次启动会事务性导入旧 `*/project.json`，保留原文件作为不再更新的备份。迁移前必须停止旧服务及其任务。原有工作区与截图位置保持不变。迁移后不要用旧版服务操作此目录，也不要继续手动编辑 JSON 期待页面同步。`STUDIO_DATA_DIR` 可指定其他数据目录。`STUDIO_JOB_TIMEOUT` 设置任务超时秒数，默认 1800；`--port` 设置 HTTP 端口，默认 3088。同一数据目录只启动一个 HTTP 服务。按 Ctrl+C 只停止网页服务，独立 Worker 继续运行。Worker 的独占文件锁防止重复执行；锁由其 Harness 子进程共同持有，因此 Worker 异常退出后，旧子进程尚未退出时不会启动第二个执行者。Worker 无心跳时页面会提示离线，排队任务仍保留；检查 `worker.log` 与旧子进程后再启动 Worker。系统不自动重试结果未知的任务。

阶段模型配置完整保留 `harness.patch.yml` 中的提供方协议、地址和凭据环境变量；该文件采用 JSON 语法（有效的 YAML 子集），不要写入真实密钥。

模型临时过载、限流、断网、超时和空响应会在同一运行中的 Harness 会话内重试失败的模型步骤。GPT.GE 默认最多重试三次，依次等待 120、240、300 秒；可在 `harness.patch.yml` 的 `retryPolicy` 调整。等待计入任务总时限，取消任务或停止 Worker 会终止恢复。执行状态显示次数和倒计时。鉴权、余额不足、无效请求及未知错误不会自动重试。不重启整个任务来重放已完成的工具；失败的部分回复被丢弃，根据已提交历史重新请求。进程被杀死或 Worker 重启后仍需明确重试，因为执行结果可能未知。每次重试可能产生 Token 费用，此策略不提供金额限额。修改策略后需重启 Worker。

## Worker 管理

默认启动命令会启动或复用独立 Worker。若单独管理两个进程，先在含模型密钥的终端运行：

```sh
python3 studio/server.py --worker
```

在另一个终端运行网页服务：

```sh
python3 studio/server.py --no-worker
```

请求停止 Worker 使用相同数据目录运行：

```sh
python3 studio/server.py --stop-worker
```

该命令请求中断当前任务，保留已有文件与排队任务。默认后台 Worker 的诊断日志在 `worker.log`，任务日志在各项目的 `job-<任务 ID>.log`；旧日志 `run.log` 保留可读。修改模型密钥后应停止并重新启动 Worker，它不会从重启的 HTTP 服务获取新环境变量。若只修改 `STUDIO_JOB_TIMEOUT`，新提交任务记录新时限，已提交任务仍使用原时限。备份 SQLite 前应停止 HTTP 与 Worker，连同项目目录及数据库伴随文件一起备份。

## GPT.GE

工作台自动加载 `harness.patch.yml`，通过 `https://api.gpt.ge/v1` 的 Chat Completions 接口连接；阶段模型选择遵循上文的模型策略。在启动终端配置 `GPT_GE_DEFAULT_API_KEY` 与 `GPT_GE_CODEX_API_KEY`，分别使用只绑定对应分组、且在 GPT.GE 关闭自动分组的两个独立令牌。分组由网关令牌决定，不通过修改模型 ID 或虚构请求头选择。缺少指定阶段令牌时明确失败，不改用另一分组。`GPT_GE_API_KEY` 仅为选择旧路由的历史排队策略保留；不要把密钥写进 YAML。模型名称、接口支持与账号渠道可用性需要以平台实际返回为准；本地配置检查不会验证账号权限。当前任务结束后重启 HTTP 与 Worker；新策略要求 `stageRouting: 1` 能力。排队任务保留提交时的模型、提供方与推理选择。本地测试验证请求中的 high 推理字段及独立凭据，不验证网关账号的令牌分组绑定或模型可用性。

运行预览代理按 64 KiB 分块转发上传。`studio-preview.json` 支持 `maxRequestBytes`（默认及最大 600 MiB）、`requestTimeoutSeconds`（默认 120、最大 600）与后端响应上限 `maxResponseBytes`（默认 64 MiB、最大 600 MiB）。响应超限返回带 traceId 的 PREVIEW_RESPONSE_TOO_LARGE JSON，不返回 HTML。代理失败与大响应大小写入预览日志，不记录请求正文、凭据或查询参数；修改配置后需重新启动运行预览。浏览器断开连接时关闭响应，不再尝试发送第二次错误。超限或代理失败返回 JSON 错误；应用自己的 GLB 几何和格式限制仍然有效。上传成功不代表模型通过校验。

带需求附件的项目提交助手问题时保留选中的页面文本；附件目录不会覆盖对话的选区上下文。

项目助手使用一体圆角输入框，图片和页面选区卡片位于消息上方，各卡片可独立删除。加号支持最多四张 PNG/JPEG/WebP 图片，每张不超过 3 MiB；最多八个页面选区分别传入上下文。输入框上方不显示对话标题和范围说明；小三角保留历史对话导航及重命名。附件草稿按对话保存在浏览器，保存失败会显示提示。发出的图片随消息保留，并复制到助手的一次性任务目录供实际读取。图片消息要求 HTTP chatImageAttachments: 1 和 Worker projectChat: 4，当前任务结束后重启两者。图片是否能被理解仍取决于模型的识图能力。

`assistantModels` 是输入框的部署模型白名单，当前包含 `gpt-6.1-sol`、`gpt-6-astra`、`gpt-6-sol` 和 `claude-sonnet-5-5`。白名单不进入持久执行策略；已提交任务保留选定模型与强度。HTTP 和 Worker 声明 `reasoningSelection: 1`，当前任务结束后重启两者以使用全部五档。本机协议测试验证发出的模型名和 reasoning_effort 字段，不验证网关对模型与强度组合的可用性及权限。不支持的组合应由网关报告错误，不静默降低所选强度。

照片或文件可拖到项目助手，也可通过加号选择。文件选择器接受所有格式，包括 GLB、PDF、ZIP、音视频及无扩展名文件。3 MiB 以内的 PNG/JPEG/WebP 照片显示缩略图；更大的照片及其他格式显示普通文件名称和大小卡片，均可独立删除。最多附带四张预览照片和四个普通文件，合计不超过 64 MiB；不支持文件夹。读取失败、超限或发送失败保留文字及已有附件。文件草稿归属各自对话；浏览器保存大附件可能失败，届时显示提示，刷新后可能需重新添加。提交的原文件保存在应用工作区外的 `chat-files/<job>` 中，历史消息可下载，并复制到助手任务。受支持的 Word/Markdown/文本额外使用已有的有界正文提取器；其他格式提供原文件，无法解析的二进制内容必须明确说明，不得声称已理解。文件消息要求 HTTP 与 Worker 支持 chatFiles: 1，当前任务结束后重启加载。jobs 接口最多接收 90 MiB JSON，以容纳有界 base64 附件；其他接口保留原限制。

助手执行时，方形按钮只中断当前对话的任务。继续发送的消息会排队，在输入框上方显示紧凑引导条，删除按钮仅取消对应排队消息，并从对话历史与后续模型上下文移除其消息及回复；条目旁的「引导」会原子保存后续任务，取消当前轮次和选中的排队消息，等待原进程退出后优先处理引导。后续任务包含原目标、新要求、附件、对话历史与已发布代码，冲突时以新要求为准。这会发起新的 Harness 调用，不恢复原模型的精确思考位置；未发布代码草稿保留在磁盘，不自动复用或发布。其他排队消息继续保留。重复引导请求复用同一后续任务；无效或提交失败的引导不改变原任务。HTTP 与 Worker 均需 assistantSteering: 1，重启两者后使用。中断与引导期间已发布预览继续可用，修改成功发布后才更新页面。

代码问答附带最多 8 KiB 预览日志与已配置的代理限制；配置值不证明已有进程正在使用这些设置。审查将用户显式提交的文件附件复制到一次性工作区并改写路径，使源码过滤不会丢失二进制验证原件。缺少解析能力或文件时仍须报告未验证。

critical、high、medium 问题进入既有的有界修复和复验流程，low 保留为一般建议。验收及导出重新检查已保存报告，旧的一般建议标签不能绕过未解决的 medium 问题。已结束但审查阻塞或证据不足的修改会明确显示验证未通过。代码任务输入包含预览诊断及已保存的已发布预览地址和参数；地址可能过期，且指向已发布版本而非新草稿。智能体仅可读取已发布预览的诊断。提交附件附带大小及 SHA-256 校验，审查副本原件缺失或改变时不能完成审查。
