# Business development

Read the confirmed design and feedback. Identify the affected frontend, API, business-rule, and database components. When frontend presentation is affected, read the adjacent frontend-design skill; preserve the approved visual identity and reference screenshots. Do not load PRD-generation guidance for implementation tasks. For a small interaction fix, keep the plan and verification proportional to the affected behavior; do not rebuild completed features.

When an API changes, update its frontend consumer and verify their interaction. Enforce permissions on the server. Keep database changes in migration files and report compatibility and data consequences. Do not edit the approved requirements to justify an implementation conflict; return the conflict for review.

Verify the requested outcome and relevant regressions, including the original symptom for bug fixes. Report actual commands and outcomes, remaining limitations, and any unverified deployment steps. A successful command or generated file alone does not establish application acceptance. Do not deploy or merge without the platform's separate approval.

Before returning, fix syntax or build failures and run relevant available checks. If input contains priorReview, continue from existing source and repair its findings and failed checks; preserve completed features and avoid rebuilding the application. State unavailable verification clearly.
